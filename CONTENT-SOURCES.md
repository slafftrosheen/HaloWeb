# HaloWeb content provenance — Quiet Light 3.0

## Sources

1. **User-supplied Halo Brand Book 3.0** (150-page 19 October 2026 visual/product specification). Reference implementation is in the uploaded design pack.
2. **Picsart Quiet Light source pack**, committed at `halo-web-quiet-light/`: all English copy, source HTML, tokens, 156 viewport/theme reference renders, animations, design kit and release handoff.
3. **Live Halo Android repository**, `https://github.com/slafftrosheen/Halo`, for Android implementation claims, local-model roles, voice provider selection, action evidence and alpha releases.
4. **Live HaloLinux repository**, `https://github.com/slafftrosheen/HaloLinux`, for CLI, SDK, durable AgentRunStore, Linux adapters and proposed device sync.
5. **Real Android test screenshots**: ten unmodified 20 October 2026 screenshots from the original configured 1.0-RC1 app in `assets/screens/captures-2026-10-20/`, with documented state limits and integrity hashes; older 13 October states remain at `assets/screens/real/`.

## Provenance rules

- A real screenshot is evidence of a displayed state on that dated test build, **not** proof that an associated action completed.
- `evidence-card` components are explanatory brand illustrations, never claimed to be app screenshots.
- Kids, native overlay and HaloLinux previews require current physical acceptance before being marketed as shipped.
- Private peer synchronization, Windows and Google Play are future directions, not existing public release capabilities.
- No generated lifestyle photos, simulated videos or hand-drawn faux-Android screens remain in the deployed site.
- English is the canonical source; Russian and Latvian translation catalogs now cover core UI, navigation, product introductions and status text. Some longer English fallback content remains; source-language review and native-language QA are pending.

## Feedback and privacy

Website itself is static; no Halo backend, analytics SDK or account collection. Alpha checklist marks are browser-local. The feedback form creates a draft via the visitor's own mail application; it does not transmit or promise successful sending. Links to providers should disclose the provider's own prices/data handling.
